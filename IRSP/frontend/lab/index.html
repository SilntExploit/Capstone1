Q6: Stop the malicious process (5 pts)

A process named 'sysupdate' is running from /tmp — not a legitimate system process name. Now that you have captured its network activity, it is safe to stop it.

kill -9 $(pgrep sysupdate) 2>/dev/null; sleep 1; pgrep sysupdate && echo 'STILL RUNNING' || echo 'PROCESS STOPPED'

sudo iptables -L OUTPUT --line-numbers | grep 203.0.113.47

Q8: Find all persistence mechanisms (5 pts)

Stopping the process is not enough — the attacker set up multiple ways to restart the malware after a reboot. Find all of them.

  1. crontab -l
  2. grep -n 'sysupdate' ~/.bashrc
  3. find /etc/systemd/system -name '*.service' -newer /etc/passwd 2>/dev/null
  4. cat ~/.ssh/authorized_keys 2>/dev/null

Q9: Remove all persistence mechanisms (5 pts)

Remove each persistence mechanism you identified. Incomplete removal means the malware will restart at next reboot.

  1. crontab -r
  2. sed -i '/sysupdate/d' ~/.bashrc
  3. > ~/.ssh/authorized_keys
  4. rm -f /tmp/sysupdate

Then verify the crontab is clear: crontab -l 2>&1

With the threat contained, focus now on restoring affected files and documenting the full incident.
